3. SHOP PC        the machine that HOLDS the pawnbroking database
-----------------------------------------------------------------------

  Already there before you start: PostgreSQL, the desktop app, the
  shop's database, and the image and backup folders at the paths the
  database points at. Java is not needed - the exe brings its own.

  Run, as administrator:

     ShopKits\NEW-INSTALLATION\5-MobileSync\PawnBrokingSyncSetup.exe

  It asks:

     Shop ID        dhineshsuganya
     Cloud API key  the mbk_ key from step 2
     Cloud URL      leave the default
     DB user        postgres
     DB password    the one pgAdmin connects with on that PC

  Then it does the rest by itself, in a console you can watch: the agent
  and its service, the config, the whole database (sync tables and
  triggers, SUSPENSE, Re+ pricing, notice mode, the desktop app's own
  tables, the repledge and ledger primary keys), the day-account Deficit
  repair, the one-time history send, and the folder checks.

  There is NO SQL to run afterwards.

  Do this when nobody is billing - on a shop with a lot of history the
  send takes a few minutes and billing waits while it runs. Leave 2 GB
  free on the drive PostgreSQL is on.

  When it finishes it shows a summary and leaves the full report at
     C:\pawnbrokingSync\logs\setup-report.txt

  Read the "Needs attention" lines. The usual one is a photo folder that
  still has the old machine's drive letter - copy the images to that
  exact path, or correct camera_temp_file_name for that company, then
  use the "Run setup again" shortcut.

  Leave the PC on. The desktop shortcut "Sync progress report" shows how
  far the queue has got, in plain numbers.

-----------------------------------------------------------------------
  IF SOMETHING LOOKS WRONG
-----------------------------------------------------------------------

  Send OTP says "Not Found"
      step 1 was skipped, or the Share account uses a different address.

  the exe said the cloud refused the key (401)
      the mbk_ key is wrong. Read it back on the admin console, shop ->
      api key. Do not mint a second one.

  no photos on the phone
      nobody has signed in on the phone yet (503), or the photo folder
      named in the report does not exist on that PC.

  the phone shows FEWER repledges than the desktop
      the report's "repledge_billing key" line said MISSING - this
      shop's repledge_bill_id values are repeated or empty, so the key
      could not be added. Find them with query A3 of
      5-OneTimeSQL\tools\repledge_why_it_is_still_wrong.sql, settle
      those rows, then run the exe again. It re-sends the repledges by
      itself once the key is in.

  the phone shows MORE repledges than the desktop
      expected for a short while after the key is added: the good rows
      sit beside the old collapsed ones. Admin console -> Housekeeping
      -> Run (not dry) clears them, and it also happens overnight.
