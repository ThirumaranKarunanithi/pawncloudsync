-----------------------------------------------------------------------
  TO UPDATE THIS SHOP  -  the whole job
-----------------------------------------------------------------------

  On the PC that holds the "pawnbroking" database, right-click

     ShopKits\EXISTING-SHOP-UPDATE\4-MobileSync\PawnBrokingSyncSetup.exe

  and Run as administrator. It asks for the shop id (balamurugan), the
  cloud API key, and the postgres password.

  ALREADY INSTALLED HERE? Then it already knows the key and the password
  - it keeps whatever is in C:\ProgramData\PawnBroking\sync.properties
  and only fills what is missing. Re-installing over the top is the
  normal way to update.

  LOST THE API KEY? Read it back - do not mint a second one, a shop
  should have exactly one live key:
     https://devpawn.magizhchi.academy/admin.html
     -> balamurugan -> api key

  It then does everything by itself: the agent and its service, the
  config, the whole database (SUSPENSE and its table, Re+ pricing,
  notice mode, the desktop app's own tables, the repledge and ledger
  primary keys), the day-account Deficit repair, the one-time history
  send, and the photo and backup folder checks.

  There is NO SQL to run afterwards.

  Do it when nobody is billing: the history goes as one step and billing
  waits while it runs. Leave 2 GB free on the drive PostgreSQL is on.


-----------------------------------------------------------------------
  READ THE REPORT IT PRINTS
-----------------------------------------------------------------------

  Also left at  C:\pawnbrokingSync\logs\setup-report.txt

     repledge_billing key      must not say MISSING. If it does, this
                               shop has repeated or empty
                               repledge_bill_id values and the key
                               cannot be added - until it is, the phone
                               shows FEWER repledges than the desktop.
                               Find them with query A3 of
                               5-OneTimeSQL\tools\
                               repledge_why_it_is_still_wrong.sql
     Repledges re-sent         a count here means the key was just added
                               and the repledges went up again properly
     Waiting to send           counts down to 0 as the queue drains
     Photo / Backup folder(s)  must be folders that exist ON THIS PC

  The usual "Needs attention" is a photo folder still carrying the old
  machine's drive letter. Copy the images to that exact path, or correct
  camera_temp_file_name for that company, then use the "Run setup again"
  shortcut.

  Leave the PC on. The desktop shortcut "Sync progress report" shows how
  far the queue has got.


-----------------------------------------------------------------------
  AFTER THE QUEUE REACHES 0
-----------------------------------------------------------------------

  1. If the report said the repledge key was just added, open
     https://devpawn.magizhchi.academy/admin.html -> Housekeeping -> Run
     (not dry). The re-sent repledges land beside the old collapsed
     rows, and this drops the old ones. Until it runs, the phone can
     show MORE repledges than the desktop - that is expected, not a new
     fault. It also happens by itself overnight.

  2. Check the two ends agree: the RAILWAY box at the top of
     5-OneTimeSQL\shops\balamurugan_setup.sql, queries R7 and R8.
     R8's legacy_key_rows must be 0.

  3. On the phone, open Today's Account for a day already closed and
     hold it against the desktop screen.


-----------------------------------------------------------------------
  THE PHONE
-----------------------------------------------------------------------

  The same APK every shop uses: ShopKits\NEW-INSTALLATION\5-MobileSync\
  Sign in as bala251282@gmail.com -> Send OTP -> the 6-digit code.

  The owner can set a password afterwards ("Use password instead" ->
  "Set / change password") so later sign-ins skip the OTP. The session
  lasts 6 months either way.

  That first sign-in matters beyond the phone: it mints the box token,
  and until it exists every photo and backup upload is refused with 503.

  Check: Stock Details, Today's Account, MIS Report, and a bill's photos
  once they have uploaded. A large shop's first image sync takes a few
  HOURS - it is throttled on purpose. Leave the PC on.
